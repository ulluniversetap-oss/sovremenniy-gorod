# УК «Современный город» — сайт

Сайт управляющей компании. Основной сайт собирается на Tilda (Zero Block + T123, GSAP), в репозитории есть вторая реализация: Next.js 16 + Payload CMS 3 (`web/`). Дизайн-эталон лежит в `design/reference/` в виде готовых HTML-страниц.

## Главное правило
Перед любой правкой интерфейса прочитай `DESIGN.md` (дизайн-система) и `DECISIONS.md` (что уже решено и что заказчик отверг). Новые экраны делай по паттернам из `design/reference/`, а не придумывай заново. Работай как senior-дизайнер и вёрстальщик: сначала смысл блока и иерархия, потом детали.

## Жёсткие правила (нарушать нельзя)
1. Название застройщика («А-Бутик», «Бутик») нигде не писать: ни в текстах, ни в alt, ни в мета-тегах, ни в комментариях кода.
2. Заголовок первого экрана главной — один H1 в три строки одного размера:
   `Дом работает — вы живёте. / Управляющая компания / Современный город`.
3. В макете нет служебных и технических надписей: нумерации секций, подсказок «скролл…», пометок «данные — пример», «шаблон».
4. Янтарный `#FFB000` только для сигналов «что-то сегодня не работает». Не для кнопок и декора.
5. Нет «особенных» домов: все ЖК равнозначны, плитки одинакового размера.
6. Телефоны — ссылки `tel:`. Логотип только утверждённый (`design/reference/logo.svg`).
7. Язык интерфейса и ответов — русский. Типографика: неразрывный пробел после предлогов и союзов до 3 букв, тире «—», кавычки «ёлочки».

## Стиль в одной строке
Тёмный графит, бетонные серые, один шрифт (Onest, для крупных заголовков Golos Text), прямоугольные элементы, линии только там, где они несут смысл, никаких гигантских шрифтов, пилюль, теней и градиентных украшений.

## Как работать
- Страницы `design/reference/*.html` самодостаточны: открой в браузере. Общий каркас (шапка, меню, линейка, подвал) один и тот же, меняется только `<main>`.
- После правки UI запускай проверку из скилла `sg-design` (`.claude/skills/sg-design/SKILL.md`): ширины 1440, 1920, 820, 390, нет горизонтального скролла, нет ошибок в консоли.
- Если задача не ясна и ошибка будет дорогой, задай один короткий вопрос. Если ясна — делай и сообщай результат.
- Данные в макетах (мероприятия, новости, районы, телефоны) — примеры. Реальные берём у заказчика.

## Файлы
- `DESIGN.md` — токены, типографика, сетка, компоненты, страницы
- `DECISIONS.md` — журнал решений и отвергнутых вариантов
- `design/SPEC-site.md` — исходное ТЗ с картой сайта и блоками (частично устарело, см. DECISIONS.md)
- `design/reference/` — эталонные страницы: `index`, `events`, `news`, `event`, `news-item`, `zhk`
- `design/data/zhk.json` — список ЖК и адресов
- `design/tools/check.py` — автопроверка вёрстки
