# Современный город — новый стек

Next.js + Payload CMS (Postgres). Живёт рядом со старым статическим сайтом
в корне репозитория — тот не тронут и останется как запасной вариант.

## Что внутри

- `src/app/(frontend)` — публичный сайт. Сейчас: заглавная страница-ссылка
  и `/events` — «Мероприятия» со списком новостей и фильтром по ЖК.
- `src/app/(payload)` — служебные Payload-роуты (`/admin`, `/api/*`),
  сгенерированы автоматически, руками не трогать.
- `src/collections` — модели данных:
  - `Users` — админы, логинятся в `/admin`.
  - `Media` — загруженные файлы (фото к новостям).
  - `News` — новости: заголовок, дата, текст, привязка к ЖК (фиксированный
    список в `src/collections/News.ts`, синхронизирован со SPEC.md), фото.

## Локальная разработка

1. `cp .env.example .env`, заполнить `DATABASE_URL` (строка подключения к
   Postgres) и `PAYLOAD_SECRET` (любая случайная строка).
2. Нужен Postgres — либо свой локальный, либо `docker compose up` поднимет
   его автоматически (см. `docker-compose.yml`).
3. `npm install && npm run dev`, открыть `http://localhost:3000`.
4. При первом заходе в `/admin` Payload попросит создать первого админа.

После правок в `src/collections/*` нужно один раз перегенерировать типы и
карту импортов:

```bash
npm run generate:types
npm run generate:importmap
```

## Продакшен / деплой

`npm run build` собирает Next.js в standalone-режиме, `Dockerfile` в этой
папке собирает рабочий контейнер (`node server.js`, порт 3000).

Схема деплоя: пуш в GitHub → Timeweb Cloud App Platform (подключён к этому
репозиторию, корень сборки — папка `web/`) собирает образ по `Dockerfile` и
обновляет приложение. База — отдельная managed Postgres в Timeweb Cloud,
подключается через `DATABASE_URL` в переменных окружения приложения.
